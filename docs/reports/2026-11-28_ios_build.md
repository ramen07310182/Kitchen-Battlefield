## 2. ワークフロー（`.github/workflows/ios-build.yml`）
- `macos-latest` で動きます。手動実行（workflow_dispatch）と、`v*` のタグの push で動きます
- 流れは次のとおりです
  1. Godot 4.7.2 の macOS 版と書き出しテンプレートをダウンロードします
     - テンプレートは大きいので、`ios.zip` だけを取り出して残します
     - 2つとも `actions/cache` でキャッシュします
  2. ヘッドレスで import → `--export-release "iOS"` で Xcode プロジェクトを書き出します
  3. `xcodebuild` で署名なしでビルドします（`CODE_SIGNING_ALLOWED=NO`）
  4. `Payload/OneOpeShokudo.app` を zip にして `OneOpeShokudo.ipa` を作ります
  5. Artifacts に上げます（30日）
  6. Releases に添付します
     - 手動実行のときは、プレリリース「latest」を消して作り直し、その時のコミットに付けます
     - タグのときは、そのタグのリリースに添付します。リリースがなければ作ります
- 失敗したときは、Godot と xcodebuild のログを Artifacts の `build-logs` に上げます
- Releases を作るために `permissions: contents: write` を付けました。使うのは GitHub が用意する `GITHUB_TOKEN` だけです

## 開発者がやること（pushしてから .ipa を手に入れるまで）
1. **バンドルID**は `com.ramen07310182.oneopeshokudo` に決まりました（何もしなくてよい）
2. **GitHub Desktop で push する**（コミット 3件）
3. **権限を確かめる**
   - GitHub のリポジトリの Settings → Actions → General → Workflow permissions を開きます
   - 「Read and write permissions」になっていなければ変えます
   - ワークフローに `permissions: contents: write` を書いてあるので、たいていはそのままで動きます。組織の設定などで止められているときだけ必要です
   - リポジトリは公開（public）にしておきます。非公開だと、macランナーの無料枠が少なくなります
4. **Actions タブ → iOS Build → Run workflow**（ブランチ main）を押します
5. **終わるのを待ちます**（初回は15〜25分ほど）
   - 赤い×になったら、失敗した手順のログと、Artifacts の `build-logs` を見ます（`docs/ios_build.md` の5）
6. **Releases の「latest」を開きます**
   - 端末の Safari で `https://github.com/<ユーザー名>/<リポジトリ名>/releases/download/latest/OneOpeShokudo.ipa` を開き、.ipa をダウンロードします
7. **SideStore で入れます**
   - VPN アプリをオンにします
   - SideStore → My Apps → ＋ → `OneOpeShokudo.ipa` を選びます
8. **更新するとき**は 4〜7 をくり返します。アプリは**消さずに**、上から入れます

正式な版を残したいときは、`v0.1.0` のようなタグを付けて push すると、そのタグのリリースに .ipa が付きます。

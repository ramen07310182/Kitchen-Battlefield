## 変更点

### 1. 文字の下が切れる問題
- テーマのフォントの `spacing_top` / `spacing_bottom` を 0 に戻した
- 料理と食材の行の中で、文字の行を重ねていた負の間隔（-1）を 0 にした
- 高さを決めている所を確認した
  - 固定の位置で置いている文字（客の表情・テーブル番号・「売り切れ」の表示など）は、Godot が文字の高さより小さくしないので、切れない
  - 一覧の行は、中の文字の高さで決まる

### 2. 長押しで詳細
- 準備画面の料理の行・食材の行の、ボタン以外の所を長押しすると、詳細のポップアップが出る
  - 料理: 料理名、価格・原価・利益、調理時間、必要な食材（すべて・個数つき）、注文の目安、今日の仕込み数と置き場、前回（仕込み・売れた・売り逃し）
  - 食材: 仕入れ値、在庫（仕込みで使う数・営業後に残る数）、仕入れ予定、必要数の目安、使う料理（すべて。料理ごとの個数と今日の仕込み数）
- 指でもマウスの左ボタンでも同じ。ホバーでは出ない
- 長押しの時間は `game_config.tres` の `long_press_time`（0.4秒）
- 指を離すと閉じる。外をタップしても閉じる
- 見出しの下に「行を長押しで詳細」と小さく書いた

### 3. 「出す／出さない」をなくした
- 仕込み数が1以上の料理を「今日出す料理」とする。ボタンはなくした
- 「目安○食」はすべての料理に出す
- 次の3つを、仕込み数が1以上かどうかで決めるようにした
  - 開店時の置き場の料理ボタン
  - 営業画面の厨房のボタン
  - 食材の「今日のメニューでは使わない」
- 出す／出さないの情報はセーブしていなかったので、セーブの移行は必要なかった
- 仕込み数が0の料理の行は、少し暗く表示する

### 4. 絵は Nearest、文字とUIは Linear
- プロジェクトの既定のテクスチャフィルタを Linear にした
- ドット絵は次のように Nearest にした
  - `SpriteView`: ノードで Nearest を指定する
  - ボタンの料理アイコンとUIの絵のスキン: 読み込み側（`SpriteLibrary`）で、Nearest を指定した CanvasTexture に包んで渡す。こうすると、ボタンの文字は Linear のまま、アイコンだけぼかさずに描ける
- 確認したこと
  - iPhone の比率で結果画面の金額を拡大して比べ、数字の端のにじみ（細い線）が消えたことを確認した
  - `tests/sprite_check.tscn` と営業画面で、仮の客の絵がぼやけないことを確認した
  - 一時的に置いた料理アイコン・床・UIの枠の絵（確認後に削除）もぼやけないことを確認した
- CLAUDE.md のテクスチャフィルタの決まりを「絵（`assets/sprites/`）は Nearest、文字とUIは Linear」に書き換えた

### 5. 売り逃し
- 料理ごとに、その料理を頼みたかったのに頼めなかった人数を数える。数えるのは次の2つ
  - **売り切れていて、別の料理を頼んだ客**
    - 客はまず今日のメニュー全体から、いつもの選び方（`OrderChooser`）で頼みたい料理を選ぶ
    - それが売り切れていたら、注文できる料理から選び直し、最初に選んだ料理を売り逃しにする
    - 席が空いていなくて来店しなかった客は数えない
  - **売り切れで閉店したあとに来店しようとした客**
    - 閉店した時点の営業時間の残りについて、いつもと同じ来店間隔（評判込み）と選び方で「来たはずの客」を数え、頼みたかった料理を売り逃しにする
- 結果画面の内訳に「売り逃し」の列を追加した
- 黄色（売り切れ）は「廃棄0かつ売り逃しが1以上」にした（凡例も「黄：売り切れて売り逃しあり」に変更）
- 準備画面の前回の表示
  - 売り逃しがあれば「前回 2食売れた（あと1食売れた）」
  - 売り逃しがなく全部売れたら「（完売）」
- セーブに前回の売り逃し（`last_missed`）を保存する

## 自分で決めた細かい仕様
- **新しい料理の調理時間と色**
  - 親子丼定食: 5秒（生姜焼きと同じ）。色は黄色（卵）。唐揚げのオレンジと区別できる明るさにした
  - 野菜炒め定食: 4秒（いちばん安いので、いちばん早く作れる）。色は緑（野菜）
  - 並び順は、既存の3品のあと（親子丼 → 野菜炒め）
- **スクロールと長押しの区別**
  - 押してから指が8px（640×360基準）以上動いたらスクロールとして扱い、押していたボタンや行の長押しを取り消す
    - ボタンの外へ指が出て離れた、という入力を送って取り消す
    - 取り消したあと指を離しても、ボタンは押されない
  - 長押しも、0.4秒たつ前に8px以上動いたら取り消す
  - 一覧がスクロールできない（全部見えている）ときは、動かしても取り消さない
  - しきい値は `game_config.tres` の `scroll_drag_threshold`、ホイールの量は `scroll_wheel_step`
- **「－＋」のタップ**
  - タップの1回分は「離したとき」に増減する（押した瞬間に増えると、スクロールしようとしただけで数が変わるため）
  - 長押しのくり返しが始まっていたら、離したときには増やさない
- **注文の目安**: 「すべての料理を出したとき」の目安にした。仕込み数を変えても目安が動かないので、比べやすい
  - 実際に出す料理が少ないと、1品あたりの注文はもっと多くなる。その分は売り逃しで次の日に分かる
- **食材の必要数の目安**: 仕込み数が1以上の料理について、「注文の目安」と「仕込み数」の多いほうで数える
- **詳細の位置**: 押している指と重ならないよう、料理の詳細は右半分、食材の詳細は左半分に出す
- **開店時の置き場**: 説明の行（「押して並べる・外す」）は、場所を空けるためになくした。「空にする」は見出しの右に移した
- **厨房のボタン**: 「唐揚 残り2」のように短い名前と残りだけにした
  - 調理時間は長押しの詳細で見られる
  - 置き場が満杯のときは、店主の欄に「置き場が満杯」と出す
- **売り逃しの計算に使う乱数**: 閉店後の「来たはずの客」は実際と同じく乱数で決まるので、同じ状況でも日によって数が少し変わる

## 未実装・既知の問題
- **準備画面の料理の一覧が狭い**: 16:9・iPhone の比率（高さ360）では、料理の行が2つ半ほどしか見えない（スクロールで見られる）。開店時の置き場の欄が高さを使っているため。料理が増える前提なら、置き場の欄を別の画面や折りたたみにするなどの見直しが必要
- **料理の2行目の食材名は「…」で省略される**: 長押しの詳細で全部見られる
- **詳細は押している間だけ出る**: 指を離すと閉じるので、読むあいだ押し続ける必要がある
- **売り逃しは「頼みたかった料理」ベース**: 席が埋まって入れなかった客や、売り切れで別の料理を頼んだ客がその料理にも満足したか、などは区別しない
- **見た目確認ツールの自動配膳**: 簡単なものなので、結果の数字はプレイの参考にはならない
- `tests/sprite_check.tscn` の一覧は、確認用なのでふつうのスクロール（ホイール・スクロールバー）のまま
- 前回からの既知の問題（お客さんがテーブルを通り抜ける、評判の上がり方が速い、iOS書き出し設定がない など）はそのまま

## 変更点

### 1. 店舗ランク
- ランクは次の4つ。名前としきい値は `data/game_config.tres` の `rank_names` と `rank_thresholds` にまとめた

| ランク | 名前 | 必要な評判 |
|---|---|---|
| 1 | 無名店 | 0 |
| 2 | 知る人ぞ知る店 | 30 |
| 3 | 人気店 | 60 |
| 4 | 有名店 | 110 |

- **上部バー**
  - 「無名店 ★評判 21」のようにランク名つきで出す
  - その下に、次のランクまでの進み具合を細い金色のバーで出す（最高ランクでは満タン）
- **ランクの上がり方**
  - ランクの判定は、営業結果のとき（その日の評判を反映したあと）に行う
  - 上がったら結果画面に「ランクアップ：知る人ぞ知る店」と出す
  - 一度上がったランクは、評判が下がっても下げない（セーブにも残す）。表示する評判の値は下がる
- **料理の解放**
  - 解放はランクに結びつけた。親子丼定食はランク2、野菜炒め定食はランク3
  - 料理データの項目は `unlock_rank`（以前の `unlock_reputation` は廃止）
  - 準備画面の解放前の表示は「野菜炒め定食　人気店で解放」にした
- ランク5以上は作っていない（企画書の構想の表は残した）

### 2. 評判の上がり方
- 以前は客1人ごとに評判がすぐ増減し（大満足 +3 など）、1日で +30〜50 上がっていた
- 新しい方法は「評判の新しい計算方法」を参照
- **来店ペースの倍率**
  - 評判1ごとに来店間隔を 0.45% 短くする
  - 評判111（有名店になるころ）で、今の上限の 0.5倍（来店ペース2倍）に届く
- 結果画面の見出しの横に、その日の評判の増減を「評判 +8」と出す（プラスは緑、マイナスは赤、0は灰色）

### 3. 結果画面のお金の出し方
- 大きく出すのは「利益」と「所持金」の2つだけにした
- 内訳は、それぞれの下に小さく出す
  - 利益の内訳: 料理売上・食材原価（廃棄分を含む）・うち廃棄・その他経費
  - 所持金の内訳: 今日の所持金の増減・今日の仕入れ代・**在庫の増減（原価）**・「利益 ＝ 所持金の増減 ＋ 在庫の増減」
- 来客数・完了した注文・帰ってしまった客・ミス・評判は、1行の小さな文字にまとめた（料理ごとの内訳の表に場所を空けるため）
- 在庫の増減は、準備を始めた時点と今の在庫を、仕入れ値で比べたもの
- スモークテストで「利益 ＝ 所持金の増減 ＋ 在庫の増減」が毎日成り立つことを確かめている

### 4. 共通
- **セーブ**
  - version 7 にした。ランク（`rank`）を保存する
  - 古いセーブ（v6以前）は、評判を新しい範囲に換算してからランクを決める
  - 換算は ×0.89 で、来店ペースが前と同じになるようにした（0.004 ÷ 0.0045）。解放済みの料理はそのまま残す
- 本物のセーブには触れていない。テストとボットは別のファイルを使い、最後に消す
- `docs/game_design.md` を次の内容に合わせた: 店舗ランク、評判の計算、上部バー、結果画面のお金の出し方
- 新しい確認ツール: `tests/reputation_sim.tscn`
  - ボットに何日分も遊ばせて、日ごとの評判の推移を表で出す
  - 使い方: `-- --skill=good|normal|sloppy --days=15 --seed=1`

## 評判の新しい計算方法
1. **営業中**: 客ごとに満足度の点数をその日の分としてためる。この時点では評判の値は変わらない

| できごと | 点数 |
|---|---|
| 大満足 | +1.0 |
| 満足 | +0.5 |
| やや不満 | −0.5 |
| 怒って帰った | −2.0 |
| 売り逃し 1人 | −0.8 |
| 違う料理を出した（ミス）1回 | −0.5 |

2. **営業結果のとき**: その日の点数の合計を評判に反映する
   - プラスの日: 点数 × 今のランクの倍率（ランクが高いほど上がりにくい）

     | ランク | 倍率 |
     |---|---|
     | 無名店 | 0.5 |
     | 知る人ぞ知る店 | 0.4 |
     | 人気店 | 0.35 |
     | 有名店 | 0.3 |

   - マイナスの日: 点数 × 0.5（少しだけ下がる）
   - 小数は四捨五入する
3. 反映したあとの評判でランクを判定する（上がるだけで、下がらない）。上がったら、そのランクで使える料理を解放する

- 例: 無名店で、20人全員を大満足にして、売り逃しが2人の日
  - 点数は 20 − 1.6 ＝ 18.4
  - 評判は 18.4 × 0.5 ＝ +9
- 数値はすべて `game_config.tres` で変えられる
  - 客ごとの点数: `reputation_great` / `_good` / `_bad` / `_angry` / `_missed` / `_mistake`
  - ランクの倍率: `reputation_gain_by_rank`
  - マイナスの日の倍率: `reputation_loss_scale`

## 自分で決めた細かい仕様
- **評判をまとめて反映するタイミング**
  - 営業結果のときにまとめて反映し、営業中は評判の値を変えない
  - 理由1: 「評判 +12」を結果画面で出しやすい
  - 理由2: ランクごとの倍率をかけやすい
  - 理由3: 来店ペースは営業開始時の評判で決まるので、営業中に変わっても意味がない
- **マイナスの日**: 倍率 0.5 で少しだけ下げる。ランクは下げない
- **売り逃しの点数**
  - 売り切れで閉店したあとに来るはずだった客も含めて数える
  - 仕込みを大きく減らした日（ミスの多いボット）は、売り逃しが多く、評判がほとんど増えない
- **古いセーブの換算**: 来店ペースが変わらないように、×0.89 にした
  - 古いルールでは評判がとても速く上がっていたので、数日遊んだセーブは高いランクから始まる
- **上部バーの進み具合**: 今のランクのしきい値から、次のランクのしきい値までの割合
  - 評判がランクのしきい値より下がった場合（ランクは下げないため）、バーは0になる

## 未実装・既知の問題
- **ボットは目安**
  - 上手なボットは、人よりも反応が速く、正確
  - 人が「上手に」遊んだ場合は、上手とふつうのボットのあいだ（ランク2が4〜5日目、ランク3が7〜10日目）になりそう
  - 実機で数日遊んでみて、しきい値を見直したい
- **来客数はテーブル4つで頭打ち**: 評判が上がって来店ペースが上がっても、1日の来客は28人ほどで止まる（席が空かないと入れない）。設備（テーブルを増やす）を作ると変わる
- **結果画面の料理ごとの内訳**: 16:9 と iPhone では2行半ほどしか見えない（スクロールで見られる）
- **テスト用に評判を上げている所**: 見た目確認ツールとスモークテスト（2日目に5品で確かめるため）は、テストのために評判を上げている（ゲームには影響しない）
- 前回からの既知の問題（お客さんがテーブルを通り抜ける、iOS書き出し設定がない など）はそのまま

## 2. 料理ごとの内訳

### 営業結果画面
- **「料理ごとの内訳」の表**: 仕込んだ料理ごとに、料理名・仕込み・売れた・廃棄・売上を出す
- **色分け**（表の上に凡例も出す）
  - **黄色（売り切れ）**: 廃棄が0＝仕込んだ分が全部売れた料理。もっと仕込めば売れたかもしれない、の目印
  - **赤（廃棄多め）**: 廃棄が仕込み数の30%以上の料理。仕込みすぎの目印。廃棄の数字も赤くする
    - 30% は `game_config.tres` の `waste_warning_ratio` で変えられる
  - どちらでもない料理は、左端に料理の色の帯だけを出す
- 表が入るように、画面のレイアウトを直した
  - 見出し「○日目の営業結果」と「今日の評価 ★」を1行にまとめた
  - 売上などの行の間隔を詰めた
  - 内訳の表はスクロールできる場所に置いた（料理が増えても「次の日へ」が押せる）
- 「売れた」は配膳できた数、「売上」はその料理の代金の合計

### 準備画面
- 各料理の行に、3行目として「前回 ○食売れた」を小さく出す
  - 前回に全部売れた料理は「前回 ○食売れた（完売）」
  - 前回出さなかった料理は「前回は出さなかった」
  - 1日目（前回の記録がない）は出さない

### セーブ
- version 4 にした。前回売れた数（`last_sold`）を保存する
- version 3 のセーブは移行時に空にする（次の営業のあとから「前回 ○食売れた」が出る）

## 未実装・既知の問題
- **売り切れの判定**: 「廃棄が0」を売り切れとしている。注文できずに帰った客（注文できる料理がない時間帯の来店）は数えていないので、「本当はあと何食売れたか」はわからない
- **怒って帰った客の分**: その料理は余るので廃棄に入る（売れなかった分として正しいが、仕込みすぎとの区別はない）
- **料理が増えたときの準備画面**: 料理が4つ以上になると、準備画面の左側の高さが足りなくなる可能性がある（今は3つで、16:9でぎりぎり収まっている）
- **iPhoneの比率での金額の文字**: 結果画面の金額の数字の端に、細い線のようなにじみが見えることがある
  - 文字にもテクスチャの「Nearest」設定がかかっているためと思われる
  - 直すなら、絵以外のUIだけ「Linear」にする方法がある（CLAUDE.md の「テクスチャフィルタは Nearest」と関わるので、今回は変えていない）
- 前回からの既知の問題（お客さんがテーブルを通り抜ける、評判の上がり方が速い、iOS書き出し設定がない など）はそのまま

## 変更点

### 1. スモークテストが本物のセーブを使わない
- `GameState` に次を追加した
  - `save_path`（保存先。普段は `user://save.json`）
  - `use_save_path(path)`（保存先を切り替え、その内容で状態を作り直す）
  - `delete_save()`
- `tests/smoke_test` は `user://save_smoke_test.json` を使い、終わったら消す
- テストの最後に「本物のセーブがテストの前後で同じか」「テスト用のファイルが消えたか」を確かめ、だめなら終了コード1で終わる
- 確認: 本物のセーブがない場合・ある場合の両方で `real save unchanged=true`

### 2. 日本語ドット絵フォント（PixelMplus）
- **選んだフォント**: PixelMplus（ピクセル・エムプラス）。作者 Itou Hiroki / M+ FONTS PROJECT
  - ライセンスは **M+ FONT LICENSE**。改変の有無・商用／非商用を問わず、使用・複製・再配布が自由（OFLと同じく再配布できる）
  - JIS第1・第2水準の漢字をすべて収録している
  - 入手元: https://github.com/itouhiro/PixelMplus （v1.0.0 / PixelMplus-20130602.zip）
- **置いた場所**: `assets/fonts/pixel_mplus/`
  - `PixelMplus12-Regular.ttf`（通常の文字）、`PixelMplus10-Regular.ttf`（小さい文字）
  - ライセンス文: `LICENSE_E`（英語）、`LICENSE_J`（日本語）、配布物の `README.txt`
  - 説明: `README.md`（入手元・ライセンス・使い方のルール）
- **設定**
  - インポート設定で、アンチエイリアス・ヒンティング・サブピクセル配置をオフにした（ドットがぼやけないように）
  - テーマ `assets/theme/main_theme.tres` の既定フォントを12pxにした。あわせて種類を2つ作った
    - `SmallLabel`（10px）
    - `LargeLabel`（24px＝12pxの2倍）
  - 各シーンの文字サイズ指定は、この3種類に置き換えた。**文字の大きさは 10・12・24 だけ使う**（それ以外だとドットがつぶれる）
- 画面で使っている177文字がすべてフォントにあることを確認した。フォントになかった「—」（評価がない日の表示）は「なし」に変えた

### 3. 在庫不足の警告と「前回と同じ仕込み」
- **在庫不足の警告**
  - 食材ごとに「今日必要になりそうな数（目安）」を出し、在庫がそれより少ないと次のように表示する
    - 行を赤くする
    - 「目安 18（8 不足）」と不足数を出す
    - 画面下に「赤い食材は今日の分が足りなさそうです」と出す
  - 目安の計算（`scripts/demand_estimator.gd`）
    - 来店数の目安 = （営業時間 − 最初の来店までの時間）÷ 平均の来店間隔（評判込み）＋ 1
    - 料理ごとの注文数 = 来店数 × 客層の割合 × その客層がその料理を頼む確率
    - 料理ごとに「注文数の目安」と「仕込みの数」の多いほうを使い、食材の数に直す
    - 席が埋まって来店できない分は考えないので、少し多めの目安になる
  - 注文の確率は `scripts/order_chooser.gd` にまとめ、実際の来店でも同じ計算を使う
  - 警告の厳しさは `game_config.tres` の `stock_warning_ratio`（1.0＝見積もりどおり。1.2にすると余裕を持たせる）
  - 確認: 評判31の日、目安20.2人に対して実際は20人来た
- **「前回と同じ仕込み」ボタン**（今日のメニューの下）
  - 前回の営業で実際に仕込んだ数を覚えておき、ボタン1つで同じ仕込みにする
  - 前回仕込んだ料理が「出さない」になっていたら「出す」に戻す
  - 食材や枠が足りない分は入れず、「食材が足りず、前回の仕込みを一部しか入れられませんでした」と出す
  - 1日目（前回がない）は押せない
- **セーブを version 2 にした**: 前回の仕込み（`last_prep`）を保存する。version 1 のセーブは読み込み時に移行する（スモークテストで確認済み）
- **準備画面の見た目の調整**
  - 各行の「仕込み」の文字をやめ、見出しを「今日のメニュー（－＋：営業前に作る数）」にした
  - 「仕込み合計 6 / 6枠」と短くした
  - 料理の食材と原価が切れずに見えるようになった

### 4. 評判で来店間隔が変わる
- 来店間隔 = （5〜9秒のランダム）× 倍率
  - 倍率 = 1 − 評判 × 0.004。下限は0.5
  - 評判50で0.8倍、評判125以上で0.5倍（間隔が半分＝2倍よく来る）
- 数値は `game_config.tres` の次の2つにまとめた
  - `interval_reduction_per_reputation`（0.004）
  - `min_interval_scale`（0.5）
- 倍率は営業開始時の評判で決め、その日の営業中は変わらない
- 準備画面の下に「評判 31：お客さんが来るペース ×1.14（平均 6.1秒ごと）」のように表示する
- 確認: 評判0で来客15〜17人、評判31〜47の翌日で20〜21人

## 遊び方の変化
- **準備画面で、まず赤い食材を見る**: 赤い行は今日の分が足りなさそう。「+1／+5」で赤が消えるまで買えば、食材切れで客を逃しにくい
- **2日目からは「前回と同じ仕込み」**: 先に食材を買ってから押すと、前回と同じ仕込みが全部入る
- **評判を上げるほど忙しくなる**: 大満足を続けると次の日の来店ペースが上がり、必要な食材も増える（目安も増える）。評判が下がるとペースも落ちる
- **文字がドット絵フォントになった**: 操作は前と同じ

## 未実装・既知の問題
- **消してしまったセーブは戻せない**（上のお詫びを参照）
- **評判の上がり方が速い**: テストでは1日で+30〜45上がるので、4日目ごろには来店ペースが上限（2倍）に届く。評判の増減か `interval_reduction_per_reputation` の調整が必要そう
- **iPadなど、拡大率が整数でない画面では、フォントのドットの太さが少し不ぞろいになる**（640×360の1.6倍・2.6倍などの場合）。iPhoneで見え方を確認したい
- **在庫の目安は多めに出る**: 席が埋まって入れなかった客も数えているため
- 前回の報告の既知の問題（お客さんがテーブルを通り抜ける、iOS書き出し設定がない、今日のメニューの選択は保存しない など）はそのまま

## 次に足すとよさそうなもの
1. **評判の上がり方の調整と店舗ランク（無名店 → 人気店）**: 評判の上限・下がり方を決めて、成長の手応えをつくる
2. **効果音（提供・ミス・調理完了・怒って帰る）**: 営業中の忙しさが伝わりやすくなる
3. **iOS書き出し（export_presets・バンドルID）とGitHub Actions**: 実機で触って、フォントやタップの大きさを確認できるようにする

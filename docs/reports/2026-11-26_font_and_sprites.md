### 太さ（FontVariation）
テーマ `assets/theme/main_theme.tres` の中で、可変フォントの太さ（wght）を変えた3種類を作った。
| 用途 | wght |
|---|---|
| 通常の文字 | 400 |
| ボタンの文字 | 500（押せる場所が少し目立つように） |
| 見出し（`HeaderLabel`）・大きい文字（`LargeLabel`） | 700 |

- このフォントは字の上下の余白が大きく、行が高くなりすぎるので、上2px・下1px 詰めている（`spacing_top = -2`、`spacing_bottom = -1`）
- フォントの既定の太さは100（細字）なので、フォントを直接使わず、必ずテーマの3種類を通して使う

### 文字サイズの決め方
- **基準**: iPhone（横向き 844×390pt）では、640×360 の1pxがおよそ1.08pt になる。iOSの文字の目安（本文17pt、小さい注釈でも11pt以上）と、画面に入る量の両方を見て決めた
- 決めたサイズ（640×360での px）

| 種類 | 大きさ | iPhoneでの大きさ | 使っている場所 |
|---|---|---|---|
| 通常 | 13px | 約14pt | ほとんどの文字・ボタン |
| `SmallLabel` | 11px | 約12pt | 食材・原価の説明、在庫の目安、来店ペース、吹き出しの料理名 |
| `HeaderLabel`（新規・太字） | 14px | 約15pt | 「今日のメニュー」「食材の仕入れ」「注文状況」「完成品置き場」「店主」 |
| `LargeLabel`（太字） | 24px | 約26pt | 営業結果の見出し・評価、営業終了の表示 |

- 「10・12・24px だけ」の制限はなくした。サイズはテーマの4種類で決め、各シーンには数字を書かない
- 画面の見直し: 文字が大きくなって次の2か所が窮屈になったので直した
  - 完成品置き場の「持っている: ○○」: 長い料理名でも枠を広げず「…」で切る
  - 注文状況の各行: 左の色の帯に文字がくっついていたので、左の余白を広げた
- 16:9・iPhone（1688×780）・iPad（1024×768）で、準備・営業・結果の3画面を撮って、はみ出し・切れがないことを確認した

## B. ドット絵の差し替え準備

### しくみ
- `assets/sprites/<名前>.png` があればその絵を、なければ今の図形を表示する
- コマ数・1コマの大きさ・再生速度・基準点は `data/sprites/<名前>.tres`（新しいデータ型 `SpriteSheetData`）で設定する。1コマの絵なら設定ファイルは要らない
  - アニメーションするもの（客・店主・コンロ）とUIの枠の設定ファイルは、推奨のコマ数で先に作ってある
  - 設定よりコマの少ない絵を置いても動く
- アニメーションは「`<名前>_<アニメーション>.png` → `<名前>.png` → 図形」の順に探す。客なら、まず1枚 `customers/<id>.png` を置けば全部の動きに使われる
- 絵はぼかさずに表示する（Nearest）。文字はフォント側でなめらかに表示される
- 主な部品
  - `scripts/sprites/sprite_view.gd`（`SpriteView`）: 絵を表示するノード。代用品の図形はこのノードの子に置き、絵があれば隠す。足元合わせ（客・家具）と、敷き詰め（床・壁）の2つの置き方がある
  - `scripts/sprites/sprite_library.gd`: 絵と設定を読み込む（1回読んだ絵は覚えておく）
  - `scripts/sprites/sprite_keys.gd`: 絵の名前（置き場所）の一覧
  - `scripts/sprites/ui_skin.gd`: UIのボタン・枠の絵があれば、テーマに入れる

### 対応した場所
| 対象 | 名前（`assets/sprites/` から） | 代用品 |
|---|---|---|
| 客（歩き・座り・食事） | `customers/<id>_walk` など | 頭と体の四角 |
| 料理 | `dishes/<id>` | 吹き出し・完成品置き場の文字、調理ボタンの色の四角 |
| テーブル・椅子 | `furniture/table`, `furniture/chair` | 茶色の四角 |
| 床・壁・入口 | `shop/floor`, `shop/wall`, `shop/entrance` | 単色の四角 |
| 店主（待機・調理中） | `kitchen/chef_idle`, `kitchen/chef_cook` | 白い四角 |
| コンロ（待機・調理中） | `kitchen/stove_idle`, `kitchen/stove_cook` | なし（絵がなければ表示しない） |
| 厨房の背景 | `kitchen/background` | 灰色のパネル |
| ボタン・枠 | `ui/button_normal` ほか, `ui/panel` | 今のボタン・パネル |

- あわせて、**テーブルを客より手前に描く**ようにし、座った客の足元が机に隠れるよう座る位置を6px下げた（「客が机の上に乗って見える」のを防ぐ）
- 客が左へ歩くときは、絵を左右反転する（絵は右向きで描く）

## 絵を置いたときの確認方法
1. 絵を `assets/sprites/` の決まった場所に置く（名前・大きさは `docs/assets.md` の一覧どおり）
   - 例: 学生の絵 → `assets/sprites/customers/student.png`（32×32。歩きなどを分けるなら `student_walk.png` 128×32 など）
   - 例: 唐揚げ定食 → `assets/sprites/dishes/karaage.png`（24×24）
2. **Godot エディタでプロジェクトを開く**（開いたままならウィンドウに戻る）。PNGが自動でインポートされる
3. 見え方を確かめる
   - **絵の一覧**: `tests/sprite_check.tscn` を開いて **F6**。全27種類の絵について、見つかったか（緑＝あり／灰色＝なし）、大きさ・コマ数・アニメーションが見られる
   - **ゲームの中**: **F5** で起動して営業を始める。客・料理・テーブルなどが絵に変わる
   - **3画面のスクリーンショット**: `tests/screenshot.tscn` を **F6**。`user://screenshots/` に準備・営業・結果の画面が保存される（本物のセーブは使わない）
4. コマ数・速さ・足元の位置がおかしいときは、`data/sprites/<名前>.tres` をエディタで開き、インスペクターで `frame_count`・`frame_size`・`fps`・`pivot` を直す
5. 会社員の仮の絵は、本物ができたら上書きする（コマ数が違えば `data/sprites/customers/salaryman.tres` も直すか削除する）

## 未実装・既知の問題
- **お客さんはテーブルを通り抜ける**: 机の奥に描かれるようになったが、歩く道すじはそのまま（前回からの既知の問題）
- **アニメーションの一部だけ置くと、見た目が混ざる**: 例えば店主の `chef_cook.png` だけ置くと、待機中は図形になる。共通の絵（`kitchen/chef.png` など）を1枚置いておけば防げる（`docs/assets.md` に書いた）
- **UIの絵が効かない場所がある**: 準備画面の各行・完成品置き場の枠・注文状況の行・テーブルの光る枠は、色で状態を表しているので、絵に差し替えない
- **フォントのファイルが大きい**: 約9.6MB。アプリの容量が増える。気になる場合は、使う文字だけに絞ったフォントを作る方法がある
- 画面にない文字（絵文字など）は、端末のフォントで代わりに表示される設定のまま（Godot の既定）
- 準備画面の下半分が空いている（文字を大きくしても余っている）。今後の項目追加に使える
- 前回の報告の既知の問題（評判の上がり方が速い、iOS書き出し設定がない、今日のメニューの選択は保存しない など）はそのまま

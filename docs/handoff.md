## 今のゲームの状態（できているもの）
- 1日の流れ：準備（①仕込み → ②仕入れ → ③置き場・今日のスタッフ）→ 営業 → 結果 → お店を強化 → 次の日
- 料理25品・トッピング5品・食材13種類。解放はランクと営業日数で決まる（1年に散らばる）
- 営業
  - 自動注文、ワンクリック調理、置き場から席へ配膳
  - 待ち時間で満足度が決まり、怒って帰る客もいる
  - 売り切れたら早めに閉店し、そのあと来たはずの客を売り逃しとして数える
- 評判と店舗ランク（4段階）。来店のペースは評判で上がり、無名店・知る人ぞ知る店のあいだは常連さんの分の評判がある
- 設備5種類（席の拡張・置き場・コンロ・フライヤー・炊飯器）
- スタッフ5人
  - 雇えるのはランクごとに1〜3人。雇うときに面接代、出勤した日ごとに日給がかかる
  - 在籍日数が終わると退職し、30日たつと雇い直せる
  - 研修は Lv1〜5
  - 出勤のシフト：毎週の休み・急な休みがある
  - 担当はホールか厨房（厨房は1人まで。店主と並んで調理し、厨房手当がかかる）
- 結果画面（料理ごとの内訳・人件費・退職）、通算の記録（グラフ・履歴）、カレンダー
- 明るい定食屋の配色（`UIColors` に集約）、タッチ操作、セーフエリア、16:9・iPhone・iPad に対応
- iOS
  - GitHub Actions で署名なしの .ipa（約30MB）を作るビルドは成功している。iPad に入れて起動できた
  - 入れ方：SideStore はサインインで落ちて使えないため、PC の iloader の「Import IPA」で入れている（7日ごとに PC から入れ直す。手順は `docs/ios_build.md`）
- テスト
  - スモークテスト160項目（`--only=` でまとまりごとに実行。`--fixed-fps 60` で約5秒）
  - 見た目の確認ツール（`tests/screenshot.tscn`）
  - バランス確認のボット（`tests/reputation_sim.tscn`、高速モードあり）

## 未解決の問題・既知の問題
- **ゲームの中身**
  - お客さんとスタッフは、家具をすり抜けて歩く（入口から席へまっすぐ移動する）
  - 評判に上限がない（最高ランクのあとも上がり続ける。来店のペースは2倍で止まる）
  - 好きな料理が売り切れたとき、客は残りから選び直すだけ。営業中に仕込みを足すことはできない
  - 効果音・BGMがない
- **見た目**
  - 絵の多く（客の一部・料理・食材・家具・設備・スタッフ）がまだなく、色の四角で代用している
  - 料理の短い名前の一部が不自然（「ミックス」など）
  - 準備③（16:9）の「今日の仕込み：…」の行と、スタッフが3人いるときの一覧は、スクロールしないと見えない
  - スタッフが厨房にいる日は、料理のボタンが1列になり、縦のスクロールが増える
  - 注文状況の長いトッピング名は「＋唐揚…」と切れる
  - 記録のグラフは、1年分を出すと棒が細くて押しにくい
- **バランス（ボットでの結果）**
  - うまい人のボットは、スタッフを雇っても利益が増えにくい
  - 下手なボットは、1年目にランク4に届かず、年末の所持金も ¥10万前後と少ない
- **テスト**
  - 高速モード（FastDayModel）は近似。歩く時間を平均にしており、調理する人も、ボタンを押した時点で決めている
- **iOS**
  - SideStore はサインインで落ちて使えない。iloader で入れているため、7日ごとに PC につないで入れ直す必要がある
  - アイコンは仮
  - `config/version` は 0.1.0 のまま
- **容量**：フォント（Noto Sans JP）が約9.6MBある

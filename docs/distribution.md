# 「ワンオペ！食堂は戦場に！？」iOS配布方針（開発用引き継ぎ）

最終更新: 2026-11-28

## 前提・条件
- エンジン: Godot 4.x（GDScriptで書く）
- 対象: iPhone / iPad。**身内だけ**に配布し、App Storeには出さない
- **ブラウザではなくネイティブアプリ**として遊べるようにする
- **完全無料**で運用する（有料のApple Developer Program（年99ドル）は使わない）
- **Macは持っていない**（手元のPCはWindows想定）
- セーブデータは**ブラウザに保存しない**（消える恐れがあるため）

## 決めた方式
**ネイティブアプリ（.ipa）＋SideStoreでのサイドロード**

1. **ビルド**: GitHub Actionsのmacランナー（クラウド上のMac）で、GodotからiOS向けに書き出し、Xcodeで**署名なしの.ipa**を作る
   - macランナーの無料枠を考えて、リポジトリは公開（public）にする想定。非公開だと無料枠が少ない
2. **配布・署名**: 各端末に**SideStore**を入れ、無料Apple IDで.ipaを署名してインストールする
   - SideStoreの初回セットアップには**Windows PCが1回必要**（Macは不要）
   - その後はSideStoreが7日の期限前に**自動で再署名**する（Wi-Fiにつながっていることと、接続用VPNアプリが動いていることが条件。ときどきSideStoreを開いて状態を確認する必要がある）
3. **更新**: 新しい.ipaをSideStoreで上書きインストールする（**同じバンドルIDで、アプリを削除せずに**入れる）

## 今の運用（2026-11-28）
- **ビルドは成功**：GitHub Actions で署名なしの .ipa（約30MB）ができ、iPad に入れて起動できた
- **SideStore は使っていない**：サインインで落ちる問題があり使えない
- 代わりに **Windows PC の iloader の「Import IPA」** で、無料 Apple ID の署名をして入れている（端末は USB で PC につなぐ）
  - 自動の再署名がないため、**7日ごとに PC から入れ直す**（アプリは消さずに上書きするので、セーブは残る）
  - 更新も同じ手順で入れる
- 手順は `docs/ios_build.md` の「3. iloader でインストールする」
- 無料 Apple ID の制限（下）は iloader でも同じ

## 無料Apple IDの制限（利用者の報告をもとにした目安で、Apple公式の値ではない）
- 1台の端末に入れられるサイドロードアプリは**3つまで**（SideStore自体が1枠使うので、残り2枠）
- 同じApple IDで登録できる端末は**1週間に3台程度**。端末の削除や管理はできず、時間が経つと枠が空く
- → 同じApple IDで端末A・B・Cの3台に入れられる。**4台目以降は別のApple IDを使う**
- 署名の有効期限は7日。期限が切れてもアプリは消えず、**セーブも残る**。再署名すれば続きから遊べる

## 開発時に守ること
### ビルド設定
- **バンドルIDは固定し、絶対に変えない**（`com.ramen07310182.oneopeshokudo` に決定。`export_presets.cfg` で設定済み）。変えると別のアプリとして扱われ、セーブが引き継がれない
- アプリ拡張（ウィジェットなど）は追加しない（App IDの枠を消費するため）
- iOS書き出しプリセットのTeam ID欄など、署名なしで書き出すときに必要な設定は要確認（ダミー値で書き出せるか検証する）
- レンダラー: ネイティブなので Mobile / Compatibility のどちらでもよい。軽さを優先するならCompatibilityも候補

### 画面・操作
- iPhoneとiPadで画面の縦横比が違うので、stretch設定は `canvas_items` ＋ aspect `expand` などで両方に対応する
- ノッチやホームバーを避ける: `DisplayServer.get_display_safe_area()` を使ってUIを配置する
- タッチ操作が前提（マウス操作を前提にしたUIにしない）
- 画面の向き（縦／横）を早めに決めて、プロジェクト設定で固定する

### セーブ機能（必須）
- 保存先は `user://`（ネイティブアプリでは、アプリ専用フォルダに普通のファイルとして保存される）
- セーブ形式に**バージョン番号**を入れる（更新で中身が変わっても古いセーブを読み込めるように）
- **セーブ引き継ぎ機能**を付ける。別の端末への移行や、誤ってアプリを削除したときのバックアップに使う
  - 方式: セーブのJSONを圧縮し、Base64などで文字列にした**引き継ぎコード**。LINEやメモで送り、貼り付けて読み込む
  - コードに**チェックサム**を入れ、壊れたコードの読み込みを防ぐ
  - 読み込む前に「現在のセーブは上書きされます」と確認を出す
- 家族への注意として「期限切れになっても**アプリを削除しない**。PC で入れ直す（iloader）」と伝える

# ゲーム設計書：ワンオペ！食堂は戦場に！？

「デイヴ・ザ・ダイバー」の寿司屋パートをベースにした定食屋ゲーム。
**営業中の忙しさ**と、**営業前後の経営の楽しさ**を両立させることを最重要とする。

- 2Dドット絵 / 斜め見下ろし / 横向き画面
- iPhone・iPadのタッチ操作が前提。開発・確認はPCで行う（マウスで操作できること）

---

## 0. 用語
| 用語 | 意味 |
|---|---|
| 仕込み数 | その日に出せる料理の数。料理ごとに 0〜上限（上限は data/ の設定）で決める。在庫に関係なく決められるが、足りない食材は仕入れないと営業を始められない。営業中に増やすことはできない。**仕込み数が1以上の料理が「今日出す料理（今日のメニュー）」** |
| 店舗ランク | 評判の値で決まるお店の格（無名店 → 知る人ぞ知る店 → 人気店 → 有名店）。名前としきい値は data/ の設定。一度上がったら、評判が下がっても下げない |
| 解放 | 店舗ランクが料理ごとに決めたランク（data/dishes/ の `unlock_rank`）に届くと、その料理を使えるようになる。一度解放したら使えたまま |
| 残り | 仕込み数のうち、まだ店主が作っていない数（営業中） |
| 置き場 | 完成した料理を置く場所。枠の数は決まっている（data/ の設定。今は6枠） |
| 開店時の置き場 | 営業開始の時点で置き場に並べておく料理。仕込み数の中から決める |
| 仕入れ予定 | 買うつもりの食材の数。「仕入れる」で確定するまで、お金も在庫も変わらない |
| 廃棄 | 営業終了時に残った料理（残り・置き場・調理中）。捨てるので、原価だけがかかる |
| 売り逃し | その料理を頼みたかったのに頼めなかった人数。売り切れていて別の料理を頼んだ客と、売り切れで閉店したあとに来店しようとした客（来たはずの客を、いつもと同じ来店間隔・注文の選び方で数える） |

**数値について**：価格・原価・調理時間・待てる時間・来店間隔・営業時間・枠の数・評判の増減などの具体的な数値は、この文書には書かない。`data/`（`game_config.tres`、`dishes/`、`ingredients/`、`customers/`）を正とする。

## 0-1. 長期のバランス方針
- **ゲームにクリアはなく、ずっと続く**（経営を続けて、お店を育てていく）
- **メニュー・食材**：ゲーム内で約365日（1年）遊ぶと、すべて解放される程度のペースにする
- **店舗ランク・設備**：プレイヤーの腕しだいで、メニューよりも長くかかる程度にする（上手な人でも1年以上かけて育てる）
- 今の解放条件・ランクのしきい値・評判の点数・設備の価格と効果は、すべて**仮の値**。最終的な調整は、料理・設備がそろってからまとめて行う
- 調整しやすい作り
  - 料理の解放条件は「店舗ランク」と「営業日数（○日目以降）」の両方で決められる（data/dishes/ の `unlock_rank`・`unlock_day`）。食材は、解放済みの料理で使うものが使えるようになる
  - 店舗ランクは data/ranks/ に1段ずつ .tres で持つ（ファイルを足すとランク5以上を増やせる）
  - 設備は data/equipment/ に .tres で持ち、レベルごとの価格・効果・必要なランクを配列で持つ（配列に足すとレベルを増やせる）
  - `tests/reputation_sim.tscn` の高速モードで、365日分の評判・ランク・所持金・解放状況をCSVに出して確かめられる

## 0-2. カレンダー
- ゲームの1日目は **2027年1月1日（金）**。営業日ごとに日付が進む
- **毎週水曜日は定休日**。火曜日の営業が終わったら、水曜日を飛ばして木曜日の準備に進む（結果画面に「明日は定休日です（次の営業は○月○日（木））」）
- 画面上部の帯には「2027/1/1（金）」と、小さく「○日目」を出す
- 準備画面の「カレンダー」で、月ごとに各日の利益を見られる（プラスは青、マイナスは赤、0は灰色、定休日は「定休」、今日は枠、まだ来ていない日は空欄）。日付を押すと、その日の結果の要約（売上・利益・来客数・評価・評判の増減）を出す。月の合計の利益も出す
- 日ごとの結果は履歴としてセーブに残す（1日1行の小さな配列）

## 1. 基本サイクル（1日の流れ）
1. **営業準備**：①仕込み（仕込み数を決める）→ ②仕入れ（足りない食材を予定に入れて確定）→ ③置き場（開店時に並べる料理を決める）の順に、1画面に1つの作業をする
2. **営業開始**：仕込み数の分の食材をまとめて在庫から使う。お客さんが来店し、注文する
3. **調理・配膳**：注文に応じて「残り」から料理を作り、置き場から提供する
4. **営業終了**：時間切れ、または売り切れで閉店し、店内の客がいなくなったら終わり。残った料理は廃棄する。売上・経費・廃棄・評価と、料理ごとの内訳を確認する。評判が届いていれば新しい料理を解放する
5. **お店の強化**：営業結果のあと「お店を強化」で設備を買う（強化しない日はそのまま次の日へ）。新メニューはランクと日数で解放 → 次の日の営業へ（※従業員は未実装）

## 2. 営業パート
### 2-1. お客さん
| 客層 | 特徴 |
|---|---|
| サラリーマン | 昼休みに来店。待ち時間に厳しい |
| 学生 | 安いメニューを好む |
| 家族連れ | 複数人で来店。注文数が多い |
| 常連客 | お店のファン。多少待ってくれる |
| グルメ客 | 料理の品質を重視する |
| 大食い客 | 追加注文（トッピング）が多い |
| 急いでいる客 | 提供が遅いと帰ってしまう |

パラメータ：注文するまでの時間、料理を待てる時間、好きな料理、予算、満足度、食事にかかる時間、支払金額、口コミへの影響

行動フロー：来店 → 着席（空いている席を探す）→ 注文 → 待機（長いと不満が増える）→ 食事 → 会計 → 退店（満足度に応じた評判の点数がその日の分にたまり、営業結果のときにまとめて評判に反映される）

### 2-2. 注文
- 着席すると注文が発生する。**最初は自動注文**（プレイヤーの操作を調理と配膳に集中させる）
- 将来の案：手動注文（客をタップして注文を受ける）
- 注文票に表示する内容：料理名、内容（ご飯・味噌汁・唐揚げ・漬物など）、価格、席の番号、待ち時間、満足度の状態
  - 今の実装：席の番号（カウンター C1〜C6、テーブル T1-1〜T3-4）・料理名・待ち時間（待ち時間が長いほど目立つ色になる）
- **注文できる料理**：「残り＋置き場＋調理中・調理待ち − すでに注文されてまだ出していない数」が1以上の料理だけ
  - 客はまず今日のメニュー全体（解放済みで、その日に仕込んだ料理）から、予算と好みで「頼みたい料理」を選ぶ。それが売り切れていたら、注文できる料理から選び直す（頼みたかった料理は売り逃しとして数える）
- **注文の確保**：注文が入った時点で、その料理を1個確保する。これで「作れない料理の注文」は出ない。怒って帰った客の分は確保をやめる
- **売り切れで早く閉店**：注文できる料理が1つもなくなったら、営業時間が残っていても新しい客は来ない。「本日分は売り切れです」と知らせ、店内の客がいなくなったら営業終了
  - 閉店しなければ営業時間の残りに来たはずの客は、売り逃しとして数える

### 2-3. 調理
- 料理ごとに必要な食材を決めておく（例：唐揚げ定食 = 鶏肉・キャベツ・米）
- 食材は営業準備の「仕込み数」の分を、**営業開始のときにまとめて**在庫から使う。営業中の調理では食材を使わない
- 営業中は、料理ボタンを押すと店主が時間をかけて1個作る（ワンクリック調理）。ボタンにはその料理の「残り」を出し、作ると残りが1減る。残りが0なら作れない
- 作った料理は置き場に入る。置き場の空き枠（調理中・調理待ちの分を含む）がなければ作れない
- **残りに戻す**：置き場の料理を持った状態で厨房の「残りに戻す」を押すと、その料理を置き場から外して残りに1戻す（いらない料理が枠をふさいだときの入れ替え）

### 2-4. 配膳
- 料理をタップして持つ → 注文したお客さんをタップして提供する
- 注文と料理が一致すれば成功、違う料理だとミス
- 提供までの時間で評価が決まる：早い＝大満足 / 普通＝満足 / 遅い＝やや不満 / 非常に遅い＝怒って帰ることがある

### 2-5. 営業中のトラブル（慣れてきた頃に追加）
注文の集中、待ち時間の超過、テーブルの片付け忘れ、従業員の疲労

## 3. 定食屋ならではの機能
### 料理と食材
- 料理は25品、食材は13種類（data/dishes/・data/ingredients/）。最初は唐揚げ・焼き魚・生姜焼きの3品で、ほかはランクと営業日数で順に解放する（1年目の最後のほうに「店主のおまかせ定食」）
- 価格・調理時間は、食材の原価と料理の豪華さで決める（高い食材・食材が多い料理ほど高く、時間もかかる）。数値は data/ を正とする
- 料理には調理の分類（揚げ物・焼き物・煮物・なし）があり、設備（フライヤー・コンロ・炊飯器）の効果を受けるかどうかが決まる
- ※ご飯の量（大盛りなど）は作らない

### 今後の予定：トッピング・追加注文
- 客が注文するときに、追加で頼んでくる（例：卵焼き、唐揚げ追加）
- 例（唐揚げ定食）：卵焼き +150円 / ポテトサラダ +150円 / コロッケ +200円 / 唐揚げ追加 +250円 / 味噌汁を豚汁に変更 +150円

## 4. 経営・成長
### 4-0. 営業準備（①仕込み → ②仕入れ → ③置き場）
1画面に1つの作業にして、広く使う。上に手順の表示（今の手順を目立たせる。タップでその手順へ移れる）、下に「戻る」「次へ」（③では「営業開始」）を置く。上部の帯（日数・所持金・評判）はそのまま出す。準備画面を開くと①から始まり、手順を行き来しても入力した内容は消えない。

- **①仕込み**
  - 解放済みの料理の一覧。仕込み数が1以上の料理が、その日に出す料理になる（「出す／出さない」の切り替えはない）
  - 仕込み数は「－＋」で決める（タップで1つ、長押しで続けて増減）。上限は設定の上限だけで、**在庫では止めない**
  - 在庫が足りない料理の行には「食材が足りません（鶏肉 2不足）」と出す。画面の端に、仕込みに使う食材の「必要数／在庫」を小さく出す（足りない食材は赤）
  - 仕込み数がその日の売れる上限になる。少ないと早く売り切れて閉店し、多いと余りが廃棄になる。**どれだけ仕込むかの読み**が経営の中心
  - 判断の材料として、料理ごとに「注文の目安（評判から見た来客数と客層の好みから計算。解放済みの料理をすべて出したときの目安）」と「前回 ○食売れた（売り逃しがあれば、あと○食売れた）」を出す
  - 「前回と同じ仕込み」：仕込み数と開店時の置き場を前回と同じにする（食材が足りなくても仕込み数は入れ、②で補う）
  - まだ解放していない料理は、一覧の最後に「評判 ○ で解放」と暗く出す（何が出てくるかの楽しみにする）
- **②仕入れ（確定式）**
  - 解放済みの料理で使う食材だけを出す
  - 「+／-」で仕入れ予定を増減する（0未満にはできない。今ある在庫は減らせない）
  - 「不足分を予定に入れる」：①の仕込み数に足りない分を、仕入れ予定にまとめて入れる
  - 「仕入れる」を押すと合計金額の確認を出し、確定するとお金を払って在庫に入る。所持金が足りなければ確定できない
  - 在庫不足の警告（必要数の目安に対して足りない食材を赤くする）は**確定した在庫**で判断する。予定どおり仕入れれば足りるかどうかも、行ごとに表示する
- **③開店時の置き場**
  - 営業開始の時点で置き場に並べておく料理を、仕込み数の中から決める（枠の数まで）。並べた分は開店直後から出せる
- **先へ進むときの確認**
  - ③へ進むとき（「次へ」でも手順の表示でも）と営業開始のとき、仕込み数に対して確定した在庫が足りなければ進めない。「食材が足りません」と出し、「不足分を予定に入れる」か「仕込み数を在庫に合わせて減らす」を選ぶ
  - 仕入れ予定が残ったまま③へ進もうとすると確認を出す（仕入れずに進んでも予定は残る）。営業開始のときに残っていればもう一度確認し、仕入れずに始めると予定は捨てる
  - 仕込み数が合計0なら営業開始を押せない
- **詳細（長押し）**：料理や食材の行（ボタン以外）を長押しすると、詳細を出す。指を離すか外をタップすると閉じる
  - 料理：価格・原価・利益・調理時間・必要な食材（すべて）・注文の目安・前回の結果
  - 食材：仕入れ値・在庫・仕込みで使う数・仕入れ予定・必要数の目安・どの料理に使うか
- **一覧のスクロール**：一覧は縦にスクロールできる（指でなぞる。PCではマウスのドラッグとホイール）。指が少し動いたらスクロールとして扱い、ボタンや長押しは取り消す

### 4-1. 営業結果
売上（料理売上）、食材原価（廃棄分を含む）、廃棄（個数と原価）、人件費、その他経費、利益、来客数、評価、完了した注文の数
- **料理ごとの内訳**：仕込み数・売れた数・売り逃し・廃棄数・売上を表で出す
  - 黄色（売り切れ）：廃棄が0で、売り逃しが1以上の料理（もっと仕込めば売れた）
  - 赤（廃棄多め）：廃棄が仕込み数の一定割合以上の料理（割合は data/ の設定）
- 売り切れで早く閉店した日は、そのことを表示する
- その日の評判の増減を「評判 +12」のように出す。ランクが上がった日は「ランクアップ：○○」、新しい料理を解放した日は「新メニュー解放：○○」と出す
- お金は「利益」と「所持金」の2つを大きく出し、内訳は小さく出す（利益の内訳：売上・食材原価・うち廃棄・その他経費／所持金の内訳：所持金の増減・仕入れ代・在庫の増減（原価））
- **お金の流れ**：仕入れ代は仕入れた時点で所持金から引く。売上は会計のとき、その他経費は営業終了のときに所持金に入る（引かれる）。食材原価は所持金からは引かない（すでに仕入れ代として払っている）
  - 利益 ＝ 売上 − 食材原価（その日に使った食材の原価。廃棄分を含む）− その他経費
  - 今日の所持金の増減 ＝ 売上 − 今日の仕入れ代 − その他経費
  - 2つが違うのは、仕入れた日と使った日がずれるため（前日までの在庫を使った日は利益が少なく見え、多めに仕入れた日は所持金が利益より減る）
  - **利益 ＝ 所持金の増減 ＋ 在庫の増減（原価）**。結果画面にはこの関係も小さく出す
- ※人件費は従業員と一緒に追加する（未実装）

### 4-2. 評判・人気度
無名店 → 知る人ぞ知る店 → 人気店 → 有名店（人気が上がるほど来店客が増える）
人気度に影響するもの：料理の品質、提供速度、接客、価格設定、メニューの豊富さ、店内の清潔さ

**今の実装（評判の計算）**
- 営業中は、客ごとに満足度の点数をその日の分としてためる（大満足・満足はプラス、やや不満・怒って帰るはマイナス）。売り逃し1人ごと、違う料理を出したミス1回ごとにもマイナス
- 営業結果のときに、その日の点数をまとめて評判に反映する
  - 点数がプラスの日：点数 × 今のランクの倍率（ランクが高いほど小さい＝上がりにくい）
  - 点数がマイナスの日：点数 × 一定の倍率（少しだけ下がる）
- 点数・倍率・ランクのしきい値はすべて data/（`game_config.tres`）の設定
- 評判が高いほど来店間隔が短くなる（有名店になるころに、来店ペースが最初の2倍ほどになる）
- 目安：上手に遊ぶと3〜4日目に知る人ぞ知る店、7〜8日目に人気店、12〜15日目に有名店。下手な日（怒って帰る客や売り逃しが多い日）は評判がほとんど増えないか、少し下がる
- 画面上部の帯に「無名店 ★評判 21」のようにランク名と評判を出し、次のランクまでの進み具合を細いバーで出す

### 4-3. 従業員（今後の予定）
- 雇うと、同時に複数の配膳ができる（今は店主1人で、配膳は1回に1品）
| 職種 | 仕事内容 |
|---|---|
| ホールスタッフ | 注文受付・料理提供 |
| 調理スタッフ | 調理 |
| 洗い場スタッフ | 食器の片付け |
| 店長補佐 | 店舗全体の業務補助 |

能力値：調理速度、接客速度、作業効率、スタミナ、給料。最初はプレイヤー1人で運営する。

### 4-4. 設備
炊飯器（ご飯の準備時間を短縮）、フライヤー（揚げ物の調理時間を短縮）、コンロ（焼き物・炒め物の調理時間を短縮）、食器棚（提供準備の効率を上げる）、テーブル（最大来店客数を増やす）、椅子（客席数を増やす）

**今の実装（設備の購入）**
- 営業結果 →「お店を強化」画面 → 次の日の準備。強化画面には、設備ごとに名前・効果・今のレベル・次のレベルの価格・必要なランクを出す
- 購入は確認ダイアログを出してから。所持金やランクが足りないものは押せず、理由を出す。行を長押しすると、今と次のレベルの効果を比べて出す
- 設備は data/equipment/ の .tres（レベルごとの価格・効果・必要なランクを配列で持つ）。価格と効果は仮の値
- 最初の5種類
  - 席の拡張：席を増やす（カウンター4席 → 6席 → テーブル1卓 10席 → 2卓 14席 → 3卓 18席）
  - 置き場の棚：置き場の枠を増やす（6枠 → 最大8枠）
  - コンロ：焼き物・炒め物（焼き魚・生姜焼き・野菜炒め）の調理時間を短くする
  - フライヤー：揚げ物（唐揚げ）の調理時間を短くする
  - 炊飯器：すべての定食の調理時間を少し短くする
- どの料理が設備の効果を受けるかは、料理のデータの分類（`cook_category`：揚げ物 fry・焼き物 grill・煮物 simmer）で決める
- 高いレベルや、テーブルの追加は、ランクで制限する
- 所持金が足りない設備は買えない（食材の仕入れは、所持金がマイナスになってもできる）

### 4-4-2. 店内と席
- 店内の上側に横長のカウンターとイス6脚、下側に4人がけのテーブル3卓（テーブルの上下にイスが2脚ずつ）。入口は右側
- **イス1脚＝お客さん1人**。テーブルは相席してよい（家族連れなどのグループは今は作らない）
- お客さんは空いているイスに座り、配膳は座っているお客さん（またはそのイス）をタップする。タップできる範囲はイスより広め
- 最初はカウンターの4席だけ。使えない席・テーブルは描かない。設備「席の拡張」で最大18席まで増える

### 4-4-3. 所持金
- 所持金がマイナスでも、ゲームオーバーにはならない。マイナスのときは、所持金を出す所すべてで「-¥12,300」のように赤で出す
- 食材の仕入れは、所持金が足りなくてもできる（確認ダイアログに「仕入れると所持金が -¥X になります」）

### 4-5. 店舗ランク
- **実装済み（ランク1〜4）**：評判の値でランクが決まる（無名店 → 知る人ぞ知る店 → 人気店 → 有名店）。判定は営業結果のときで、一度上がったら評判が下がっても下げない
- **料理の解放はランクに結びつける**：最初は基本の定食3品。ほかの料理は、料理ごとに決めたランクに届くと営業結果のあとに解放する（準備画面では「知る人ぞ知る店で解放」のように出す）。客は解放済みでその日に仕込んだ料理から注文し、売り逃しも解放済みの料理だけで数える
- 以下はランクの構想（ランク5以上と、料理以外の解放は未実装）

| ランク | 解放内容 |
|---|---|
| 1 | 基本の定食 |
| 2 | 新しい料理・トッピング（トッピングは今後の予定） |
| 3 | 従業員の雇用（今後の予定） |
| 4 | 厨房設備の拡張 |
| 5 | 新しい客層 |

## 5. 画面
- **上部の帯（各画面）**：日付と○日目、所持金、店舗ランクと評判（次のランクまでの細いバー）、営業中は残り時間
- **営業画面**：店内マップ（カウンター・テーブル・イス）、お客さん、厨房・調理器具（料理ボタンと残り、「残りに戻す」）、置き場、**注文状況（画面の端に常に表示）**、営業の残り時間（売り切れ時は売り切れの表示）、所持金、管理ボタン
- **営業準備画面**（①仕込み → ②仕入れ → ③置き場）：今日のメニューと仕込み数（注文の目安・前回売れた数・食材の不足・長押しで詳細・まだ解放していない料理）、食材の仕入れ（在庫・仕入れ予定・必要数の目安・不足分を予定に入れる・「仕入れる」・長押しで詳細）、開店時の置き場、販売価格、従業員の配置、設備、営業開始
  - ※販売価格の変更・従業員の配置・設備は未実装
- **お店を強化画面**：設備の一覧（効果・レベル・価格・必要なランク・購入・長押しで詳細）、次の日へ
- **営業結果画面**：評価と評判の増減、ランクアップ・新メニュー解放、利益と所持金（内訳は小さく。所持金の増減・仕入れ代・在庫の増減）、料理ごとの内訳（売り逃しを含む）
- **メニュー開発画面**：料理一覧、必要な食材、調理時間、原価、販売価格、利益、人気度、開発の条件
- **経営管理画面**：所持金、売上・利益の履歴、来客数、人気度、従業員、設備、ランク
